The phrase is swapped for a sentinel BEFORE names are linked, then restored as an afterwards. That is what keeps a phrase which contains (or equals) a member name from producing a nested — the sentinel hides it from the name pass, so such a phrase links out and is simply not name-linked. Doing it the other way round nests anchors, which is invalid HTML and makes the inner link unreachable by keyboard. Don't reorder these blocks. NAMES ARE LINKED IN TWO PASSES for the same reason. Pass 1 swaps every name and alias for a %%P%% sentinel; pass 2 turns the sentinels into . The trailing %% is what keeps one sentinel from matching inside a longer one.
